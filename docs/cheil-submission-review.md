# CheilOffice 제출 전 점검

2026-10-29 기준. 광고대행사 캠페인 업무와 My Wiki의 추가 개발 기능을 중심으로 제품을 설명한다. 기반 편집 엔진까지 새로 개발한 것으로 표현하지 않는다. 출처·저작권·라이선스는 NOTICE와 LICENSE에 유지한다. Git 커밋과 원본 기술 의사결정 이력은 재작성하지 않는다.

## 제출 설명에 강조할 구현

- 캠페인 문서 양식과 캠페인 단위 자료 관리
- 원자료 → 정리된 업무 지식 → 반영 대기 → 변경 로그의 사용 흐름
- 기존 AI 연결을 활용한 의미 비교와 근거 확인, 사용자 항목별 판단
- 원문·수정 이력·검토 이력 보존
- 사용자별 카카오 나챗방 연결과 명시적 전송

## 확인된 검증 범위

설치본의 My Wiki 질문 → Codex 답변 → 카카오 나와의 채팅 전송을 수행했고 사용자가 수신을 확인했다. 설치본에서 자료 8건과 45건/17건의 검토 이력 보존을 확인했다. 실제 보고서의 의미 비교에서는 45건이 생성됐으나 묶음 재분석 응답은 검증에 실패하여 폐기했다. 현재 17건은 기존 검증된 Codex 결과를 원문 기준으로 묶은 별도 검토본이다. 이를 새 모델의 자동 묶음 정확도 검증 성공으로 설명하지 않는다.

## 우선 보완

1. 새 사용자 환경: AI·카카오 인증이 없는 새 프로필에서 최초 연결 안내와 만료/재연결 절차 확인. 현재 실수신 검증은 이 PC 한 계정 기준이다.
2. 모델 신뢰성: 결정 단위 묶음 응답이 검증에 실패하면 원인 안내와 재시도/기존 검토본 재사용 흐름 제공. 자동 묶음 품질은 미해결이다.
3. 카카오 사용성: 200자 초과 답변의 명시적 요약 기능, 연결 해제/저장 인증 삭제, 단순 토큰 존재와 서버 연결 유효성 표시 분리. 전송 결과의 실제 성공/실패 내용도 확인 필요.
4. 안내 일치: 21개 언어 중 카카오 화면은 현재 한국어/영어만 표시되므로 나머지 번역 보완. 가져오기 한도와 저장 방식에 관한 오래된 문서 설명은 현재 코드와 대조 필요.
5. 제출 범위: 시험 문서·실제 업무 문서·사용자 데이터·토큰·백업·디버그 포트 파일을 제출 패키지에 포함하지 않는다. 설치본에 인증을 함께 배포하지 않는다. 코드 제출 시에도 빌드 결과와 개인 실행 기록을 제외한다.

## 문서 정리 범위

README와 개발 기록은 제품 기능 중심으로 정리했다. 브랜드가 잘못 남아 있던 개인정보/보안 안내를 수정하고 카카오 데이터 전송을 추가했다. NOTICE, LICENSE, 제3자 고지, 기술 호환 식별자와 원본 Git 이력은 보존한다. 기존 프로젝트 기술 문서는 자체 개발 성과로 재명명하지 않는다.

문서 점검에서 SECURITY.md의 이전 프로젝트 신고 URL·메일과 끊어진 안내 링크를 발견해 현재 배포본 연락처 및 NOTICE/라이선스 안내로 수정했다.
