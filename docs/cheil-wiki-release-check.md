## 적용한 내용

1. 자체 MD 위키: 파일 선택·드롭 경로·제목/본문 붙여넣기 → 일반 Markdown. 검색·읽기·직접 편집·페이지 링크·이력 복원·외부 편집 충돌 보호. 기본 저장소는 문서/Cheil 위키이며 옵션에서 변경 가능. 기존 볼트와 파일은 자동 이동하지 않는다. Obsidian은 선택 열기/기존 내보내기 옵션이다.
2. 캠페인 자료: 캠페인 화면에서 넣으면 해당 캠페인에 연결. 같은 자료를 여러 캠페인에 연결하고 연결만 해제할 수 있다. MD는 하나만 저장한다. 캠페인 검색·AI 근거 선별은 메인 프로세스에서 제한한다. 근거 발췌와 출처를 보여주며 답을 위키 초안으로 저장할 수 있다.
3. 문의처: 사용자 지정 champ.lee@samsung.com을 제품 상수·정보 화면·README·NOTICE에 반영했다. 메일의 실제 수신 여부는 확인 필요다. 메일을 발송하지 않았다.
4. 검수: 아래 실행 결과와 제한을 기록했다. 실제 사용자 프로그램을 업데이트하거나 삭제하지 않았다.

## 미완료: 정상 삭제 실행

시험용 `CheilOffice Wiki QA`의 삭제 실행을 Windows가 두 실행 방식에서 모두 '액세스 거부'로 차단했다. 정상 삭제 성공이나 삭제 프로그램의 데이터 보존을 확인했다고 표시하지 않는다. 원인이 이 실행 환경의 권한 제한인지, 회사 보안 정책인지 확인 필요다. 사용자는 지금 직접 확인하기 어렵다고 답했다.

시험 설치는 별도 식별자·고유 제거 등록 키를 사용했고, 파일 연결·PATH 등록·바로가기 생성을 제외했다. 이 검수는 일반 배포 설치 프로그램의 모든 레지스트리 동작을 검증한 것이 아니다. 이전/새 실행 파일로 설치·교체·기존 자료 보존을 확인했다. 설치된 app.asar는 최종 배포본과 동일한 SHA256이다. 이후 변경은 미디어브리프의 인쇄 설정뿐이며 해당 최종 자원도 원본과 일치함을 확인했다.

삭제 차단 후에는 제가 만든 시험 경로와 고유 등록 항목만 수동 정리했다. 기존 제품 등록·PATH가 유지됐고 위키·기존 볼트 MD 2개 및 가상 사용자 문서는 보존됐다. **수동 정리는 정상 삭제 프로그램 시험 통과를 대신하지 않는다.**

## 추가 확인 필요

- 서명 인증서가 없어 설치 파일은 NotSigned다. 회사 PC의 다운로드·설치·삭제 정책 확인 필요.
- Solar/OpenRouter 등 사용자 API 키별 응답 품질, 다른 버전 간 업그레이드, 실제 프린터 출력 확인 필요.
- 스캔 PDF OCR·복잡한 표/이미지 원형 재현·매우 큰 저장소의 성능 확인 필요.
- 실제 OS 파일 끌어놓기 제스처는 별도 확인 필요. 파일 선택·가져오기 및 드롭 처리 경로는 구현했다.

커밋·푸시·외부 게시·의존성 설치는 하지 않았다. 앱 설치는 승인받은 별도 시험 설치만 수행했다.
