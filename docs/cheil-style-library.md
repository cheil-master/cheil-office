# 스타일 라이브러리와 선택형 로고 도구

2026년 10월 28일. 승인한 스타일 화면을 실제 앱의 전용 콘텐츠 영역에 연결했다. 브랜드 로고는 업무 도구에 추가하고 검색창을 접힌 선택 옵션으로 제공한다.

## 사용 방법

홈의 **내 양식 → 스타일만 추출**에서 저장한 DOCX·PPTX·XLSX를 고른다. 별도 로컬 작업 프로세스가 글꼴 이름, 색, 크기, 기본 도형 종류를 분석한다. 사용할 글꼴·제목과 본문 크기·강조색·본문색·바탕색을 조정해 미리 본 뒤 **저장**한다. 문서 본문, 사진, 로고와 폰트 파일은 스타일에 포함하지 않는다.

스타일은 앱의 데이터 폴더에 Markdown으로 저장되며 재실행 후 **저장한 스타일**에서 다시 불러온다. MD 열기·내보내기·가져오기와 서식 지시문 복사를 지원한다. MD를 외부에서 수정한 뒤 이전 화면의 값으로 저장하면 버전 충돌로 거절해 외부 수정을 보존한다.

**새 문서 만들기**에서 Word·PowerPoint·Excel을 선택하면 지정한 폰트·색·크기의 시작 문서를 저장하고 해당 편집기에서 연다. 기존 작업물을 자동으로 재서식화하는 기능은 아니다. 공개 카탈로그 스타일을 사용하면 원본 링크·저작자·라이선스·변환 사실을 문서 속성과 출처 파일에 함께 기록한다. 서식의 정확한 배치를 복제하지 않으며, 설치되지 않은 글꼴은 대체될 수 있다.

getdesign은 사용자가 고른 항목의 색·크기 토큰만 가져온다. 전체 브랜드 Markdown이나 브랜드 자산을 설치본에 싣지 않는다. 카탈로그는 CC BY 4.0의 출처 표시 조건으로 사용하며 로고·사진·외부 폰트 파일은 제외한다. [콘텐츠 이용 조건](https://github.com/CaesiumY/ko-design-md/blob/main/LICENSE-CONTENT), [브랜드 자산 고지](https://github.com/CaesiumY/ko-design-md/blob/main/NOTICE).

**업무 도구 → 브랜드 로고 → 검색**을 펼쳐 브랜드명을 찾는다. 검색 결과에서 형태와 라이선스를 확인하고 원본 페이지를 열 수 있다. 사용 조건을 확인한 뒤 SVG를 저장하면 출처 고지 파일도 함께 저장한다. 첫 검색 전에는 로고 데이터를 요청하지 않는다. 앱 미리보기에서 지원하지 않는 SVG는 원본에서 확인하도록 안내한다. [공식 연동 명세](https://github.com/GLINCKER/thesvg/blob/main/docs/cdn-api.md), [로고 권리 고지](https://github.com/GLINCKER/thesvg/blob/main/LEGAL.md).

## 검증

- 관련 단위 시험 28개와 기존 양식·캠페인 회귀 시험 35개, 총 63개 통과.
- 21개 UI 언어의 새 스타일·로고 문구를 검증했다.
- 셸 전체 TypeScript 검사, 변경 코드 ESLint 오류 0, Prettier 검사 통과. Home.tsx의 기존 quickLookPayload 훅 의존성 경고 1개는 유지한다.
- 개발 실행본과 배포 실행본에서 각각 12개 동작 검수 통과. 격리된 실제 PPT 추출, MD 저장, 원문 제외, 외부 MD 수정 충돌, 앱 재시작 후 스타일 재사용, 기존 내 양식 입구, 실제 공개 로고 검색·미리보기·저장을 확인했다.
- 새 DOCX·PPTX·XLSX를 각각 실제 편집기에서 열고 생성한 제목·본문이 표시됨을 확인했다. Word의 실제 렌더링에서 맑은 고딕과 선택한 강조색 `#B84021`을 대조했다. 새 문서 XML과 출처 속성도 단위 시험으로 확인했다.
- 스타일 화면의 1024px·720px, 로고 화면의 720px에서 가로 넘침을 검사했다. 라이트·다크 화면도 확인했다. 두 실행본 검수의 브라우저 실행 오류는 0건이다.
- ASAR의 메인·preload·스타일 추출 작업자가 검수한 빌드와 일치하고, 편집기 8종·필수 네이티브 엔진·라이선스 고지가 존재함을 확인했다. 개인 설정과 검수 프로필은 ASAR에 포함하지 않았다.
- 배포 실행본에서 실제 getdesign 항목을 선택하고 저장해 출처·CC BY 4.0 고지 보존을 확인했다.
- Setup을 설치 없이 추출한 2,798개 파일을 실행 검수본과 SHA256으로 대조했다. 누락·불일치 0개이며 필수 리소스·개인 설정 제외와 latest.yml의 크기·SHA512도 확인했다.
- 영어 주석 검사와 diff 검사는 통과했다. 저장소 전체 테마 검사는 기존 `WikiPanel.css:186`의 `var(--border-color, #777)` 1건 때문에 실패했다. 해당 파일은 이번 변경 대상이 아니며 마지막 수정은 오전 11시 36분이다. 새 스타일 CSS에서는 위반이 검출되지 않았다.

실제 AI 요청은 하지 않았다. 손글씨·kordoc OCR 모델은 이번 승인 범위의 구현에 추가하지 않았다. 해당 모델의 검토 결과는 `docs/cheil-style-integration-review.md`에 남아 있다. 새 문서 3종을 모든 외부 Office 버전에서 왕복 편집한 결과나 실제 설치·삭제·업그레이드 시험은 아니다.
